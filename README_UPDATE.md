# Система управления версиями
## Обзор
#### Скрипты для автоматического управления версиями проекта:
```bach
- `Bump-Version` - изменение версии с записью в историю
- `Update-Version` - синхронизация версии в файлах проекта
```

## Основные файлы
```bach
1. `VERSION` - текущая версия проекта
2. `VERSION_HISTORY.log` - журнал изменений версий
3. `version-config.json` - конфигурация для замены версий
```

## Использование Bump-Version
### Команды
```bach
update-version-bump [command] [version] [options]
```

### Пример
```bach
update-version-bump ver 1.5.7
update-version-bump ver 1.5.6 force
```

### Основные команды:
```bach
major - старшая версия (1.2.3 → 2.0.0)
minor - минорная версия (1.2.3 → 1.3.0)
patch - патч-версия (1.2.3 → 1.2.4)
ver [version] - установка кастомной версии
show - показать историю версий
help - показать справку
```
### Опции:
```bach
--force - принудительное понижение версии (так как при вызове через composer нет интерактивного режима)
```
### Примеры
#### Увеличить минорную версию
```bach
composer update-version-bump minor
```
#### Увеличить мажорную версию
```bach
composer update-version-bump major
```
#### Установить конкретную версию
```bach
composer update-version-bump ver 1.5.7
```
#### Принудительное понижение версии
```bach
composer update-version-bump ver 1.0.0 --force
```
#### Показать историю изменений
```bach
composer update-version-bump show
```

## Особенности работы
### Авто-инкремент версий:
```sh
При вызове без параметров используется patch
Версия нормализуется до 3 компонентов (1.2 → 1.2.0)
```
### Защита от downgrade:
```sh
В интерактивном режиме: запрос подтверждения
В неинтерактивном режиме: требует --force
```

### Пример интерактивного подтверждения
```sh
WARNING: You are DOWNGRADING version from 2.0.0 to 1.5.0
    Do you want to continue? (y/N)
Журналирование:
    Все изменения записываются в VERSION_HISTORY.log
    Формат: YYYY-MM-DD HH:mm:ss - from -> to (type)
```
### Обновление файлов:
```sh
После изменения версии автоматически запускается Update-Version
Обновляются все файлы из version-config.json
Обработка ошибок
Некорректная версия:
Требует формат X.Y.Z (1.2.3)
```
```sh
ERROR: Invalid version format: 1.a.2
Отсутствующие файлы:
```
```sh
Конфигурация: version-config.json not found

Файлы для обновления: WARNING: composer.json not found
```
### Остановка операций:
```sh
При ошибках возвращается ненулевой код выхода
Прерывание цепочки выполнения в CI/CD
```

### Ключевые логика

1. **Работа с параметрами:**
    - Поддержка как коротких так и длинных параметров
    - Автоматическое определение позиционных аргументов
    - Обработка `--` для отделения параметров

2. **Интерактивные режимы:**
    - Определение типа терминала для downgrade
    - Автопропуск подтверждений при `--force`

3. **Валидация версий:**
    - Проверка формата версии (только цифры и точки)
    - Сравнение компонентов для определения downgrade
    - Нормализация версий перед сравнением

4. **Журналирование:**
    - Автоматическое создание истории версий
    - Четкое определение типа операции:
        - `(major/minor/patch)`
        - `(ver)`
        - `(ver down)` для понижений

5. **Интеграция:**
    - Каскадное обновление файлов через Update-Version
    - Единая точка конфигурации в version-config.json
